From Words to Systems: The Evolution of the Agentic Stack

The most important code in an agent system is not the agent itself — it is the code that wraps, constrains, and directs it. Over four years, the unit of engineering has shifted from a single prompt, to a context window, to a runtime harness, to an autonomous loop. Each layer didn't replace the previous; it absorbed it.

The Thesis: Words Cannot Constrain Compute

"You shouldn't be prompting coding agents anymore. You should be designing loops that prompt your agents."
— Peter Steinberger, June 2026

LLMs are probabilistic reasoning engines. Production systems demand deterministic behavior. This fundamental mismatch is what every layer of the agentic stack attempts to resolve.

Prompt engineering assumed you could phrase your way to reliability. You cannot. Context engineering recognized the problem wasn't wording — it was what the model could see. Harness engineering recognized the problem wasn't visibility — it was what the model could touch. Loop engineering recognized the problem wasn't a single action — it was the entire cycle of acting, evaluating, and continuing.

Each Layer is a Different Unit of Control

A prompt controls one model response. Context controls one invocation's information environment. A harness controls one agent's execution boundary. A loop controls one agent's behavior cycle over time. Each layer preserves the layer beneath it — a prompt doesn't disappear once a loop is built around it.

The Four Layers: Definition and Emergence

Layer 1 · 2022–2023
Prompt Engineering
Writing and structuring the instruction for a single model call. The only lever was language. Solved: getting a model to produce a useful single response. Failed: "linguistic optimism" — the assumption that clear phrasing guarantees compliance in multi-step autonomy.
Layer 2 · 2024–2025
Context Engineering
Designing exactly what the agent sees — not just the prompt, but the entire token configuration. RAG pipelines, file attachments, context compaction, prompt caching. Solved: keeping agents oriented across step 30. Failed: context rot — accumulated outputs degrade reasoning over long sessions.
Layer 3 · 2025–2026
Harness Engineering
The deterministic wrapper around a probabilistic model — tools, permissions, sandboxes, memory, validation gates. The agent physically cannot execute outside its boundary. Solved: making agents reliable for hours. Left open: when to act, when to stop, who escalates.
Layer 4 · 2026–Present
Loop Engineering
Designing structural controls around an agentic loop: state machines, iteration limits, tool boundaries, verification gates, and human escalation paths. Moves from human-in-the-loop to human-on-the-loop. The system prompts the agent, not the human.

Era of Linguistic Optimism

Manual Prompting — User types, model responds

Human initiates every turn. The only lever is language. No memory, no tools, no context management. Each interaction is independent. Phrasing is everything.

Layer 1: Prompt Engineering (2022–2023)

What it is: Writing and structuring the instruction for a single model call. Separate system prompts into labeled sections — background, instructions, tool guidance, output format — delineated with XML tags or Markdown headers.

Why it emerged: Early LLMs (GPT-3, ChatGPT) were single-turn. The only lever was language.

What it solved: Getting a model to produce a useful single response.

The Wall It Hit: Linguistic Optimism

The assumption that the model will behave if you phrase instructions clearly enough. In multi-hour autonomous execution, phrasing cannot prevent hallucination, unauthorized actions, or context drift. A prompt is a suggestion — it can be reasoned around, ignored, or misinterpreted.

Layer 2: Context Engineering (2024–2025)

What it is: Designing exactly what the agent sees — not just the prompt, but the entire token configuration in the context window. Includes RAG pipelines, file attachments, context restructuring into clean JSON payloads, and prompt caching to save up to 90% in token costs.

Why it emerged: As agents moved from single-turn to multi-step, the context window became a finite resource. The engineering problem shifted from "finding the right words" to "optimizing the utility of tokens against model constraints."

What it solved: Keeping the agent oriented across step 5, step 15, step 30.

The Wall It Hit: Context Rot

The gradual degradation of reasoning quality as context fills with accumulated tool outputs, prior responses, and stale instructions. Even with perfect context management, a finite window cannot hold infinite session history without loss.

Layer 3: Harness Engineering (2025–2026)

What it is: The discipline of designing the scaffolding — context delivery, tool interfaces, planning artifacts, verification loops, memory systems, and sandboxes — that surrounds an AI agent and determines whether it succeeds or fails on real tasks.

"Agent = Model + Harness. A harness is the deterministic wrapper around a probabilistic model. It reduces the space in which the model can be wrong."
— The core equation of harness engineering

Why it emerged: Production agents needed to run for hours, touch real systems, and make irreversible decisions. The model couldn't self-regulate.

The Seven Layers of a Production Harness

  • Normalization
    Standardize inputs before they reach the model.
  • Context Orchestration
    Manage what enters the context window and when.
  • Constraint Layer
    Define what the agent can and cannot do — permissions, tool access, action boundaries.
  • Gated Execution
    Require approval or verification before irreversible actions.
  • Validation & Repair
    Check outputs against expectations; auto-correct when possible.
  • Graceful Degradation
    Fall back safely when the model fails or tools are unavailable.
  • State Management
    Persist agent state across sessions, crashes, and resumptions.

The Five Structural Primitives

Primitive
Filesystem
Durable state + collaboration surface. If it's not in the repo, it doesn't exist for the agent.
Primitive
Code Execution
Autonomous problem-solving capability. The agent can run code to verify its own outputs.
Primitive
Sandbox
Isolation + verification. Actions execute in a contained environment before affecting production.
Primitive
Memory
Cross-session persistence. The agent remembers decisions, preferences, and context across invocations.
Primitive
Context Management
Compaction against context rot. Active management of what stays, what gets summarized, what gets dropped.
Evidence of Convergence

LangChain improved Terminal Bench 2.0 from 52.8% to 66.5% through pure harness changes — no model change. OpenAI shipped ~1M lines of production code without manually written source in a five-month experiment. The enabler in both cases was environment design, not model capability.

Layer 4: Loop Engineering (2026–Present)

"My job is to write loops."
— Boris Cherny, Head of Claude Code, Anthropic

What it is: The software engineering discipline of designing structural controls around an agentic loop: state machines, iteration limits, tool boundaries, verification gates, and human escalation paths. It makes loops that are not only capable but also safe, auditable, and deterministic enough for production.

The Three Functional Stages of a Loop

  • Observation
    The agent perceives its environment and current state.
  • Decision
    The agent reasons about what to do next.
  • Action & Evaluation
    The agent acts, then a separate process evaluates the result against a completion condition. The loop continues or terminates based on that evaluation.

The Maker/Checker Pattern

Separation of Concerns

The agent that writes code should never be the one grading it. A separate, independent process verifies the output. This separation is what makes asynchronous execution trustworthy — you're not relying on the same probabilistic system that produced the work to also judge it.

The Six Core Pillars

Pillar
Automations
Event-driven triggers — webhooks, timers, CI events, issue creation. The loop activates without human initiation.
Pillar
Worktrees
Isolated execution environments. Each loop iteration operates on a clean copy, preventing state pollution between runs.
Pillar
Skills
Reusable capability modules. Encapsulated procedures the loop can invoke without re-specifying instructions.
Pillar
MCP Connectors
External tool interfaces via Model Context Protocol. Standardized access to external services and data sources.
Pillar
Sub-Agents
Delegated parallel workers. Complex tasks fan out to specialized agents that report back to the orchestrating loop.
Pillar
External Memory
Persistent context across loop iterations — AGENTS.md, memory files, session state. The loop doesn't start from scratch.

The Cross-Cutting Mental Model

Many engineers treat context, harness, and loop as a sequential pipeline — data flows A → B → C. This is wrong. The correct model is cross-cutting: the harness and the loop are orthogonal axes that operate simultaneously.

The Operating System Analogy

The prompt is a single syscall. The context is the process's memory space. The harness is the kernel's permission system — what the process can touch. The loop is the scheduler — when the process runs, for how long, and when it gets preempted. These aren't stages in a pipeline. They're orthogonal, always-on systems.

Practical Implications for Teams

Practice
Evaluate the Model-Harness Pair
A strong model performs poorly without stable interfaces, structured memory, and scoped permissions. A more modest model can outperform it when the harness reduces ambiguity and constrains destructive actions. Evaluate the system, not the model alone.
Practice
Document the Harness as First-Class
Make state-changing actions interruptible, resumable, and reversible. Apply least-privilege tool governance with explicit approval gates. The harness configuration is as important as the model selection.
Practice
Repository = Primary Interface
If something is not in the repo, it does not exist for the agent. Repository legibility — how easily an agent can find, read, and act on project knowledge — determines the capability ceiling.
Practice
Start Restrictive, Expand on Evidence
New agents begin with read-only permissions and mandatory checkpoints. Track violation rate. Expand permissions where violations would have been safe. Calibrate based on data, not assumptions.
The Co-Evolution Warning

Models trained with specific harnesses can become overfitted to those designs. Harness architecture choices have lasting consequences beyond the immediate task. Design for portability.

What Comes Next: Graph Engineering

The stack may not end at loops. A potential fifth layer — graph engineering — controls the organization of many agents rather than one agent's behavior cycle. Each layer preserves the layer beneath it, and the pattern suggests the next unit of control is multi-agent topology.

The Closing Thought

The evolution from prompt engineering to loop engineering is not a story of replacement. It's a story of containment. Each layer emerged because the previous one could not contain the complexity of real-world execution. The prompt contains the instruction. The context contains the information. The harness contains the execution. The loop contains the behavior over time. And the question for the next era is: what contains the loops?
