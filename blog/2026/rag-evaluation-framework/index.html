Beyond "It Looks Good": A Production RAG Evaluation Framework

If you can't measure the quality of your RAG system, you can't confidently improve it. This guide covers how to build a production-grade evaluation framework — comparing open-source (RAGAS) with managed (Amazon Bedrock AgentCore Evaluations), with architecture patterns for offline, online, and CI/CD-integrated pipelines.

Why RAG Evaluation Matters

Teams spend weeks experimenting with embedding models, chunking strategies, rerankers, prompts, and LLMs. A change may feel like an improvement because it produces a few impressive examples — but without structured evaluation, there is no objective way to answer:

Question
Did retrieval actually improve?
Changing the embedding model or chunk size might help some queries and hurt others. Without metrics, you'll never know the net effect.
Question
Did hallucinations decrease?
A model upgrade that sounds more fluent might actually hallucinate more. Faithfulness metrics catch this before users do.
Question
Is the newer model worth the cost?
A 3x more expensive LLM that only improves answer quality by 2% might not justify the spend. Evaluation quantifies the tradeoff.
The Real Problem

RAG systems have multiple moving parts — ingestion, chunking, embedding, retrieval, reranking, prompting, and generation. If the final answer is wrong, the problem could be at any stage. Without evaluating each stage independently, debugging becomes guesswork.

The Evaluation Lifecycle

Evaluation is not a one-time activity — it's a continuous cycle that begins before the system is even deployed. The lifecycle starts with synthetic test set generation and loops back through human review at every stage.

  • 1. Synthetic Test Set Generation
    LLMs automatically generate evaluation questions, expected answers, and relevant contexts from your enterprise documents. This creates a representative benchmark dataset without months of manual curation. Tools like RAGAS TestsetGenerator or custom prompting pipelines produce diverse question types — factual, multi-hop, reasoning, comparison — covering the breadth of real user queries.
  • 2. Human Review & Curation
    Domain experts review the synthetic test set — validating questions for relevance, correcting expected answers, removing duplicates, and adding edge cases that synthetic generation missed. This human-in-the-loop step transforms a rough synthetic set into a golden benchmark dataset that reflects real-world complexity.
  • 3. Run Evaluation Against the Agent
    Execute the curated test set against the RAG system. Collect traces (question → retrieved context → generated answer) and compute metrics across retrieval and generation stages. This establishes the performance baseline.
  • 4. Iterate on Configuration Changes
    Whenever the agent configuration changes — new embedding model, updated chunking strategy, prompt modification, LLM upgrade, reranker tuning — re-run the evaluation against the same golden dataset. This ensures every change is measured, not assumed to be an improvement.
  • 5. Compare Results Against Baseline
    Generate per-question verdicts (PASS / IMPROVE / FAIL) by comparing candidate scores against the baseline. Use weighted metric thresholds to determine whether the change is a net positive. Identify regressions early — before they reach production.
  • 6. Human Review of Results & Feedback Loop
    Stakeholders and domain experts review evaluation results — especially low-scoring questions and borderline verdicts. Their feedback feeds back into the cycle: updating the test set with new edge cases, refining expected answers, adjusting metric weights, or identifying areas where the rubric itself needs improvement.
Why Start with Synthetic Generation?

Creating evaluation datasets manually is expensive and slow — typically taking weeks for a team to produce a few hundred questions. Synthetic generation produces thousands of diverse questions in hours, covering corner cases humans wouldn't think to test. The human review step then ensures quality without the bottleneck of manual creation from scratch.

The Feedback Loop is Critical

Step 6 is what separates mature evaluation from a one-shot benchmark. Human feedback refines the test set over time — adding questions that exposed real production failures, removing outdated questions after system changes, and continuously raising the quality bar. The golden dataset evolves with the system.

Evaluation as a Pipeline

Rather than evaluating only the final answer, production systems evaluate multiple stages independently. This separation identifies exactly where quality is lost.

  • Stage 1: Retrieval Evaluation
    Did the system retrieve the right information? Measures whether relevant documents make it into the context window.
  • Stage 2: Generation Evaluation
    Did the LLM use the retrieved context correctly? Checks faithfulness, relevance, and completeness of the generated answer.
  • Stage 3: End-to-End Evaluation
    Does the overall system meet user expectations? Measures task success, latency, cost, safety, and user satisfaction.
Key Insight

A system can have perfect retrieval but poor generation (LLM ignores context), or perfect generation but poor retrieval (right answer for the wrong reasons). Evaluating stages independently reveals which component to optimize.

Quantitative vs Qualitative Evaluation

Statistical
Quantitative Metrics
Objective numerical scores: Precision, Recall, Hit Rate, MRR, NDCG, ROUGE, BLEU, METEOR. Repeatable, easy to compare over time, integrated into dashboards. But can't capture nuance.
LLM-as-Judge
Qualitative Metrics
An LLM evaluates outputs against criteria: helpfulness, faithfulness, clarity, groundedness, completeness. Scales better than human review while capturing nuances statistical metrics miss.

The most effective evaluation strategies combine both — statistical metrics for regression detection and automated benchmarking, LLM-as-Judge for quality dimensions that require reasoning.

Architecture: Offline, Online, and Hybrid

A production evaluation system operates across three modes:

Pre-Deploy
Offline (Batch) Evaluation
Run against curated benchmark datasets before deployment. Compare candidate vs baseline using golden datasets. Gate deployments on metric thresholds. Regression testing for every change.
Post-Deploy
Online (Live) Evaluation
Continuously monitor production traffic. Sample a percentage of sessions (e.g., 10%). Track quality trends over time. Alert on degradation. No golden dataset needed — evaluates against rubrics.
On-Demand
Targeted Investigation
Evaluate specific sessions or traces. Investigate reported issues. Validate fixes. Analyze historical data. Useful for debugging and root-cause analysis of quality problems.

Evaluation Pipeline Architecture

  • Ingest
    Collect agent traces (question, retrieved context, generated answer, tool calls) — via OpenTelemetry, application logs, or direct API capture.
  • Enqueue
    Queue evaluation jobs (SQS, Kafka, or managed service). Decouple evaluation from the serving path to avoid latency impact.
  • Evaluate
    Workers execute metric computations — statistical metrics in parallel with LLM-as-Judge scoring. Multiple evaluators run concurrently per trace.
  • Store
    Persist scores with full lineage (trace ID, evaluator version, model used). Enables historical trending and A/B comparison.
  • Verdict
    Compare against baselines — generate PASS/IMPROVE/FAIL verdicts per question using configurable thresholds and weighted metrics.
  • Report
    Dashboard visualization, CloudWatch metrics for alerting, natural-language summaries for stakeholders, and CI/CD gate decisions.

RAGAS: Open-Source Evaluation

RAGAS (Retrieval Augmented Generation Assessment) is the most widely adopted open-source framework for RAG evaluation. It provides both retrieval and generation metrics, all computed using LLM-as-Judge under the hood.

Core Metrics

Metric Category What It Evaluates
Faithfulness Generation Claims in the answer supported by retrieved context
Answer Relevancy Generation Whether the answer addresses the question asked
Answer Correctness Generation Semantic similarity to a reference answer
Answer Similarity Generation Surface-level similarity to reference
Context Precision Retrieval Proportion of retrieved context that is relevant
Context Recall Retrieval Proportion of relevant information retrieved
Context Entity Recall Retrieval Named entities from ground truth found in context
Context Utilization Generation How effectively the model uses retrieved context

Agentic Evaluation Metrics

For multi-turn agent interactions, RAGAS provides:

Agent
Agent Goal Accuracy
Did the agent achieve the user's stated goal across the full multi-turn interaction? Evaluates end-to-end task completion.
Agent
Tool Call Accuracy
Did the agent invoke the correct tools with the right parameters? Measures whether the agent's reasoning led to appropriate tool selection.
RAGAS Strengths

No vendor lock-in. Fully extensible. Works with any LLM provider. Integrates into CI/CD pipelines. Active open-source community. Supports custom metrics. Reference-free evaluation possible (no golden dataset required for some metrics).

Amazon Bedrock AgentCore Evaluations

AgentCore Evaluations is AWS's managed evaluation service. It uses LLM-as-Judge techniques with both built-in and custom evaluators, integrating with OpenTelemetry and OpenInference instrumentation.

Evaluation Types

Continuous
Online Evaluation
Monitors live production traffic continuously. Configurable sampling (e.g., 10% of sessions). Conditional filters for targeted evaluation. Aggregated dashboards with trend tracking.
Targeted
On-Demand Evaluation
Evaluate specific spans or traces by ID. Investigate customer interactions. Validate fixes. Analyze historical data. Ideal for build-time testing and issue investigation.
Bulk
Batch Evaluation
Process multiple sessions in a single async job. Supports ground truth via session metadata. Pre/post comparison for prompt or model updates. Regression testing across curated sets.

Built-in Evaluators

AgentCore provides pre-configured evaluators accessible via ARN (e.g., Builtin.Helpfulness). These use optimized prompt templates and cannot be modified — ensuring consistent scoring baselines.

Custom Evaluators

Define domain-specific evaluation criteria with custom prompt templates and evaluator models. Custom evaluators are private resources with IAM-based access control — enabling team-specific quality criteria without exposing evaluation logic.

AgentCore Strengths

Fully managed — no infrastructure to maintain. Native integration with Strands and LangGraph agents. OpenTelemetry trace ingestion. Session sampling and filtering. Aggregate dashboards built-in. Supports up to 1M input/output tokens per minute per account.

CI/CD Integration: Evaluate Before You Ship

Every change to a RAG system — embedding model, chunk size, retriever, reranker, prompt, LLM — should be validated against evaluation benchmarks before deployment.

CI/CD Evaluation Pipeline

  • Trigger
    PR or commit triggers evaluation workflow (GitHub Actions, Jenkins, or any CI).
  • Run Candidate
    Execute the changed RAG system against the golden evaluation dataset. Collect traces (question, context, answer).
  • Evaluate
    Run RAGAS metrics (or AgentCore batch evaluation) on collected traces. Compute all configured metrics.
  • Compare
    Compare candidate scores against the baseline. Generate per-question verdicts (PASS / IMPROVE / FAIL) with configurable thresholds.
  • Gate
    Block deployment if weighted metric score drops below threshold. Report results as PR comments or CI annotations.
  • Promote
    On pass, the candidate becomes the new baseline. Store results for historical tracking.
A/B Testing in Practice

Instead of relying on intuition, run A/B tests against the same evaluation dataset. Compare retrieval metrics, generation metrics, latency, and cost. Only promote changes that demonstrate measurable improvements across the metric set.

Custom Domain-Specific Rubrics

Generic metrics are rarely sufficient in enterprise environments. A technically correct answer may still fail because it omitted required information, violated policies, or missed domain-specific criteria.

Domain
Regulatory Compliance
Does the answer comply with industry regulations? Are required disclaimers present? Are citations to approved sources included?
Domain
Citation Completeness
Are all factual claims traced to a source? Are references valid and verifiable? Does the citation format match organizational standards?
Domain
Business Rule Validation
Does the answer respect business constraints? Are deprecated configurations flagged? Are prerequisite conditions mentioned?
Domain
Knowledge Coverage
Does the answer utilize all relevant internal knowledge? Are cross-references to related topics included? Is context from multiple sources synthesized?

Both RAGAS and AgentCore support custom rubrics — RAGAS through extensible Python classes, AgentCore through custom evaluator resources with configurable prompt templates.

Evaluation Maturity Model

Teams don't need to build everything at once. A practical path to production-grade evaluation:

  • Level 1: Manual Spot-Checks
    Human reviewers sample outputs periodically. No automation. High cost, low coverage. Where most teams start.
  • Level 2: Offline Benchmarks
    Golden dataset + automated RAGAS metrics in a notebook. Run before major changes. First measurable quality baseline.
  • Level 3: CI/CD-Gated Evaluation
    Every PR runs evaluation automatically. Deployment blocked on metric regression. Verdict system compares candidate vs baseline.
  • Level 4: Online Monitoring
    Live traffic evaluated continuously. Dashboards track trends. Alerts on quality degradation. Sampling-based to control cost.
  • Level 5: Continuous Optimization
    Evaluation drives automated A/B testing. System self-optimizes (prompt tuning, retrieval strategy selection) based on metric feedback loops.
The Bottom Line

The most successful teams treat evaluation as a first-class component of their architecture — just as important as retrieval, prompting, or model selection. A mature framework combines statistical metrics for objectivity, LLM-as-Judge for nuance, custom rubrics for domain relevance, and continuous monitoring for production safety.
